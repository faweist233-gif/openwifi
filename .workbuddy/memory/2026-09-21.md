## 修复：openwifi 预编译镜像下载被截断

**现象**：`xz -dk openwifi-1.5.0-shahecheng.img.xz` 报 `Compressed data is corrupt`。

**诊断**（实测）：
- `~/Downloads/openwifi-1.5.0-shahecheng.img.xz` 只有 `1984993104` 字节，应为 `3318391904` → 只下到 **59.8%**，是截断不是比特损坏。
- `xz -l` 失败（尾部 index/footer 不存在）；前 200MB 用 `xz -t` 报 `Unexpected end of input`（头部数据本身没问题）。
- 干扰项：文件最后两字节恰好是 `59 5a`（xz 流尾魔数 YZ），差点误判成"尾部完整、头部缺数据"；`xz -l` 一测即否定。**单看 `tail -c 2` 不足以判断**。

**根因**：ugent 服务器跨名单连接吞吐极低（实测 33~83 KiB/s），长连接中途断掉。

**解决**：服务器支持 `accept-ranges`（Range 探测返回 206，17 字节）。写了分段并发续传脚本 `/tmp/ow_resume.sh`：
- 16 路并发分段，实测合计 **~1459 KiB/s**（8 路为 979 KiB/s，单连接仅 33~83 KiB/s，差 12~30 倍）→ 瓶颈在单连接链路效率，多连接有效。
- 每段用 `curl -r a-b >> p$i` 追加，**不用 `--retry`**（会重复追加），靠外层轮次从 `cur` 偏移继续，可重复执行续传。
- 全段长度校验通过后按序 `cat` 拼装，再删分段目录。

**踩坑**：脚本里 `"$TOTAL（还需"` 这种「变量紧跟全角括号」被 bash 当成变量名的一部分（`set -u` 下报 unbound variable）。**Shell 脚本中变量一律写 `${VAR}`**，不要让它紧跟中文全角标点。

**结论**：大文件跨国下载优先用多连接分段，别指望单连接续传。

## 续：补齐到全尺寸后仍有损坏（分层校验定位法）

**现象**：分段补齐后文件大小精确等于 `3318391904`，分段目录已自动清理，但 `xz -t` 仍报 `Compressed data is corrupt`。注意此时 `xz -l` 已能正常读出索引（1 stream / 634 blocks / 14.8 GiB / CRC64）→ 证明**不是截断，是中间字节真坏**。

**关键分层（这套顺序以后直接复用）**：
1. `xz -l` 能读索引 → 容器结构在，问题在块数据里。
2. `tail -c 12 | xxd` 解析 stream footer：CRC32 OK、魔数 `YZ`、Backward Size `0x499` → 索引字段长 `(1177+1)*4 = 4712` 字节。
3. 手写 Python 解析索引（VLI 为 7-bit little-endian）：读取 record 数 = 634，逐条解出 `(unpadded_size, uncompressed_size)`；索引 CRC32 自校验 OK；推算压缩总长与文件长度吻合（差额 831 字节 = 634 块的 4 字节对齐补齐累计，正常）。**索引 100% 完好**。
4. 逐块独立校验：取 `[comp_off, comp_off+unpadded)`，前面拼 12 字节流头，喂给 Python `lzma.LZMADecompressor(format=FORMAT_XZ)`。liblzma 在块结束处会校验块内 CRC64，坏块抛 `LZMAError: Corrupt input data`。634 块全扫只要 **101 秒**。

**结果**：坏块 = **第 215~285 块，共 71 块**，是**一段连续区域**：
- 压缩偏移 `1,339,116,640` ~ `1,985,974,188`（616.9 MiB，占文件 40.4%~59.8%）
- 第 1~214 块 OK，第 286~634 块 OK
- 区间末端 `1,985,974,188` 恰好对应**原始那条 116 分钟单连接下载的断点 59.8%** → 那趟长连接在 40% 之后写进去的字节是坏的（最初的"截断"把这段损坏掩盖了：文件短了，`xz -l` 先因缺索引失败，看起来只是没下完）。

**结论（重要教训）**：**"文件大小对了" ≠ "文件没问题"**。长连接中断后即便续传补齐，中断前写入的中间段仍可能是坏的。以后凡是分次/长时间下载大压缩包，一律用逐块校验而不是只比大小。

**工具已落到项目**：`tools/xz_block_verify.py`（逐块校验，打印坏块清单）、`tools/ow_range_reget.sh`（只重下损坏区间再拼新镜像，16 路并发）。

**修补方案**：只重下 616.9 MiB 损坏区间（约 10 分钟），拼成 `openwifi-1.5.0-fixed.img.xz` 后重扫。
**另一个坑**：`xz --robot -lvv` 对本文件只列出前 215 块就停了（对照测试：合成的 367 块文件能全列），所以**别依赖 `-lvv` 的块清单**，要自己解析索引。

## E316 四个 SMA 口的对应关系（查证）

**丝印顺序（实物照片放大读出，参考位号 J10/J12/J13/J14）**：`TX/RX1`、`RX1`、`RX2`、`TX/RX2`。

**权威依据 = openwifi 自己给 e310v2 画的框图** `kernel_boot/boards/e310v2/README.assets/struct.png`（1671×918，右侧画了前端）：每通道 `TX_nA` 与 `RX_nA` 各经 balun 进 SP2T，两个 SP2T 交叉相连，分别通到 `TXRXn` 和 `RXn` 两个 SMA。即：
- `TX/RX<n>` = 通道 n 的双向口（TXA 与 RXA 经 SP2T 合到同一个 SMA）
- `RX<n>` = 通道 n 的另一条接收路径（纯收）

**两侧固件的端口选择一致**：openwifi `kernel_boot/boards/e310v2/devicetree.dts` 与微相 Pluto 固件补丁 `MicroPhase/antsdr-fw-patch → patch/e310v2/0001-add-support-linux.patch` 都是 `adi,rx-rf-port-input-select = <0>`（RX1A/RX2A）、`adi,tx-rf-port-input-select = <0>`（TX1A/TX2A），且微相那份还加了 `-lock-enable`。→ 两家固件收发都走通道 1/2 的 **A 口**。

**结论/建议**：openwifi 默认 SISO 只用通道 1 → **接一根天线到 `TX/RX1` 即可**；`RX1`/`RX2` openwifi 用不到；`TX/RX2` 仅在用第二路接收（`side_ch` 监测通道）时才需要。因为前端有 SP2T 且固件不控它，**"RX1A 到底从 TX/RX1 还是 RX1 进来"无法从固件确定**，用 RSSI 实测：`cat /sys/bus/iio/devices/iio:device0/in_voltage0_rssi`（或 `./rssi_openwifi_show.sh`），天线在两个口之间换、看哪个口 RSSI 跳。

**顺带修正**：默认 AP 是 `hw_mode=a` + `channel=36`（5 GHz / 5180 MHz），见 `user_space/hostapd-openwifi.conf`；`country_code=BE`。之前写的 ch44 是错的。天线要覆盖 5 GHz。

**附件对应**：包装含 2 根胶棒天线 + 1 根吸盘天线；吸盘是 **GPS** 天线，接板子左缘的小同轴口（旁边丝印 `PPS/10M` 是外部参考输入），不是 SMA。

## 更正：TX / RX 不在同一根天线上（前端开关是固件控的）

承上。用户追问"发射和接收是不是都在这同一根天线上"，继续查下去，**推翻上面那条"接一根 `TX/RX1` 即可"的建议**。

**1）SP2T 其实是固件控的，驱动里写得很明确**（`driver/sdr.c` `openwifi_set_antenna()`，约 1500–1588 行）：

```c
ctrl_out.en_mask = priv->ctrl_out.en_mask;
ctrl_out.index = (target_rx_ant==0 ? AD9361_CTRL_OUT_INDEX_ANT0 : AD9361_CTRL_OUT_INDEX_ANT1);
ad9361_ctrl_outs_setup(priv->ad9361_phy, &(ctrl_out));   // 写 AD9361 CTRL_OUT → 驱动板上开关
tx_intf_api->TX_INTF_REG_ANT_SEL_write(fpga_tx_ant_setting);   // FPGA 侧选 TX 链
rx_intf_api->RX_INTF_REG_ANT_SEL_write(target_rx_ant);         // FPGA 侧选 RX 链
```

`driver/sdr.h`：`AD9361_CTRL_OUT_INDEX_ANT0 = 0x16`、`ANT1 = 0x17`、`en_mask = 0xFF`。设备树里也有 `adi,ctrl-outs-index / -enable-mask`。
→ 所以"TX 走哪个口、RX 从哪个口进"**是 openwifi 设的，不是固定接线**。

细节：`rx_ant` 1/2 → `target_rx_ant` 0/1 → ANT0/ANT1；`tx_ant` 1/2/3（链0 / 链1 / 两链），**TX 侧"选天线"靠给另一条链灌满衰减**（`AD9361_RADIO_OFF_TX_ATT`），不动物理开关；`priv->ctrl_out.index` 在 `openwifi_start` 附近（`sdr.c:2436`）也按 `rx_intf_cfg` 初始化为 ANT0/ANT1。

**2）openwifi 的 AD9361 跑 FDD**（设备树 `adi,frequency-division-duplex-mode-enable`）→ TX 与 RX 射频通路**同时在线**；自发时只静音 RX 基带（`iq_2ant.md`：`./sdrctl dev sdr0 set reg xpu 1 1` 解静音）。→ 同一根天线不可能同时收发 → **默认必然分口：TX → `TX/RX1`，RX → `RX1`（两根天线）**。

**3）旁证**：微相文档 `AntsdrE316_Unpacking_examination` / `E310_...` 那句"连接天线到RX1端口"是**真的**（E200 也是 1T1R 板，才可能是套用）；AntSDR 在 UHD 下输出 `Antennas: TX/RX, RX2`（见 E200/U200/U220 文档页），与 ADI B210（TX/RX 共口 + 独立 RX2，FDD 下 RX 必须走 RX2）同源。厂商选型表：E310/E316 = **2T2R MIMO**，E200 = SMA:1T1R。

**4）顺手澄清两个过时/易误读的东西**：
- `user_space/set_ant.sh` **不存在**（master 与 v1.5.0 都 404），`doc/app_notes/iq_2ant.md` 里引用它是过时文档；实际选天线走标准 mac80211 天线 API（`iw phy ... set antenna`）。
- `user_space/set_tx_port.sh` 写 AD9361 寄存器 `0x004`（0x43/0x44），选的是**芯片内部 TX 端口 A/B**（TX1A / TX1B），不是 SMA。

**5）仍无法只靠文档确定的一点**：开关的**出厂/上电默认态**（RX1A 究竟先落到 `TX/RX1` 还是 `RX1`）。做法：RSSI 实测 —— 只插 `TX/RX1` 读一次、只插 `RX1` 读一次，`cat /sys/bus/iio/devices/iio:device0/in_voltage0_rssi`（或 `./rssi_openwifi_show.sh`）；同时 `dmesg | grep openwifi_set_antenna` 会打印 `tx_ant1 rx_ant1` 与 `ctrl_out sel 16/17`。

**已同步改动**：`ANTSDR-E316-openwifi-烧录指南.md` 的 A1 物料、A4 接线表与说明全部改为"两根天线（`TX/RX1` 发 + `RX1` 收）"，并补了 `CTRL_OUT` 的证据链。

- 每个子目录 .c 都是**一个 platform driver**，用 `module_platform_driver(dev_driver)` 注册，`of_device_id` 的 compatible 就是设备树里的 `sdr,tx_intf` / `sdr,rx_intf` / `sdr,xpu` / `sdr,openofdm_rx` / `sdr,side_ch`。→ **一个 .ko ↔ 一个 platform_driver ↔ 一个 dtb 节点**，这解释了"IP↔dtb↔驱动"三元组。
- `sdr.c` 还 `#include "git_rev.h"`（make_all.sh 生成）+ 三个 ADI 头：`<../../drivers/iio/adc/ad9361_regs.h>`、`ad9361.h`、`ad9361_private.h`、`<../../drivers/iio/frequency/cf_axi_dds.h>` —— 所以 sdr.ko **必须对着 ADI 内核源码树编**，不能脱离内核树单独编译。
- insmod 期模块参数（改行为不用重编）：`sdr.ko` → `test_mode`、`init_tx_att`；`side_ch.ko` → `num_eq_init`（0~8，CSI 尾附均衡器输出数）、`iq_len_init`（>0 则开 IQ 抓取、关 CSI）。
- IP 封装 = `boards/package_ip_complex.tcl` 里 `ipx::package_project -vendor user.org -library user -taxonomy /UserIP -import_files`，在 `ip_repo/<ip>/` 产出 `component.xml`（IP-XACT，Vivado 靠它识别 bus interface/参数）+ `xgui/` + 源文件副本；`ip_repo_gen.tcl` 第 69 行硬编码 `set ip_name_list "openofdm_rx openofdm_tx rx_intf tx_intf xpu side_ch"`。给 IP 传参靠"生成 `ip_repo/*.v` 再拷进各 IP 的 `src/`"（openwifi_hw_git_rev/board_def/clock_speed/spi_command/fpga_scale/has_side_ch_flag.v）；**用户自定义宏的正确落点是 `boards/<板>/ip_config/<ip>_pre_def.v`**（打包时 cat 追加到 `src/<ip>_pre_def.v`），改它不污染仓库。
