## 核心技术结论（已按源码/BD 核对，最终版）

**1. CSI 与 IQ 互斥，位置在 side_ch 搬运层**
`side_ch_control.v:313` 的 2:1 mux（`side_info = iq_capture==0 ? CSI : IQ`）→ 单 m00_axis FIFO → 单 DMA → PS。三重设计约束：单 FIFO/单 DMA（BRAM + 通道）、定长记录协议（驱动按"每记录元素数"整除 `M_AXIS_DATA_COUNT`）、reg4/reg5 双重用途、CSI 组装 FSM 被 `if(iq_capture==0)` 门控（`:436,479`）。`side_ch.c` 明说 `iq_len_init>0 → csi disabled`。7Z020 N≤4095≈204.75 µs。

**2. 来源层一切同源（此前的错误表述已更正）**
不是"CSI 与 IQ 无关"，而是"**CSI 不是从 side_ch 抓的那份 IQ 算的**"。`system.bd` 证明 `rx_intf_0/sample0` = `openofdm_rx_0/sample_in` = `side_ch_0/sample0_in` 是同一根线。三者是同一份样本的三次投影：快照=原样时域 / CSI=L-LTF 段 FFT 后÷训练序列 / 解码帧=同步+纠正+均衡+译码后的比特。

**3. CSI 物理来源**
`equalizer.v:219` `csi = csi_valid ? {lts_i_out,lts_q_out}:0`；`calc_mean.v` 做 `H[k]=(Y1[k]+Y2[k])/2×L_LTF[k]`（两个 LTF 平均抗噪，±1 参考即取反）。`csi_valid` 门（`:217`）：非 HT 第 1 个 OFDM 符号 / HT 第 5 个。CSI 段 56 项 = `HT_SUBCARRIER_MASK` 的 ±1..±28（HT/非 HT 都用这套，FIFO 内始终 64 项按掩码取 56）。**FCS 失败包同样有 CSI**（早于 FCS 判定）。

**4. 快照 ≠ 解码器输入**
解码器吃的是经时域 `rotate` + 频域 `rot_after_fft` 两级纠相位后的样本；IQ 快照是未纠正原样。且解码器是有状态机 + 离散分支（`addr1`/`fft_win_shift`/`pkt_ht`/smoothing/watchdog），同一段 IQ 换切窗点解不出来 → 不能从快照离线重建解码结果。从 IQ 复算 CSI 可行但不会与 FPGA 逐位相同。

**5. 触发机制**
CSI：6 态 FSM 按 FC→addr1→addr2 匹配（reg1 match_cfg + reg5/6/7），等 `last_ofdm_symbol_flag`，TSF 锁存于 `pkt_header_valid_strobe`，**与 FCS/RSSI 无关**。
IQ：`iq_trigger_select`(reg8) 32 选 1，触发时 `iq_raddr=iq_waddr-pre_trigger_len` + 锁存 TSF。条件 25（addr 匹配）与 CSI 共用同一组寄存器 → 分时两阶段可选同一批包。

**6. E316 接收链硬件（本轮新增，`boards/e310v2/src/system.bd` 实测）**
- 时钟三域：`adc_clk`=40 MHz（AD9361 l_clk→divclk，ADC 域）；`clk_wiz_0` 40→100 MHz = `m_axi_mm2s_aclk`（**全 openwifi IP 工作时钟**，含 openofdm_rx/side_ch/DMA）；`ps_clk`=FCLK_CLK0。
- 模拟→数字：AD9361（`rf_init.sh`: 40 MSPS、RX BW 17.5 MHz、AGC fast_attack、RX/TX LO 1 GHz）→ `axi_ad9361` → `util_ad9361_adc_fifo` → `util_ad9361_adc_pack`（打包 64 bit）→ `openwifi_ip/adc_data` → `rx_intf` 内 `adc_intf` **÷2**（`adc_valid_decimate=(adc_valid_count==0)`）→ 基带 20 Msps。`board_def.v`: `SAMPLING_RATE_MHZ 20`、100 MHz 下每样本 5 个时钟。
- `openwifi_ip` 层次含 **6 个用户 IP**：rx_intf/tx_intf/openofdm_rx/openofdm_tx/xpu/side_ch + axi_dma_0/1 + 3 个 interconnect。⚠ `ip/openwifi_ip.tcl` 只列 5 个（无 side_ch），只有 `openwifi_ip_ultra_scale.tcl` 有 → 以板级 BD 为准。
- DMA：`rx_dma`(0x80410000) **S2MM ← rx_intf/m00_axis**（解码帧）、MM2S → side_ch/s00_axis；`tx_dma`(0x80400000) MM2S → tx_intf/s00_axis、**S2MM ← side_ch/m00_axis**。dts 里 `sdr` = `<&rx_dma 1>,<&tx_dma 0>`；`side_ch_0` = `<&rx_dma 0>,<&tx_dma 1>`。

## 术语澄清（PL/PS · ADI · FDD/TDD · ADC 通道）

- **PL = Programmable Logic**（Zynq 的 FPGA 侧，SRAM 型配置、掉电即丢）；**PS = Processing System**（双核 ARM 侧）。bitstream 在 FSBL 阶段配置；PS 经 AXI 地址映射访问 PL（`sdrctl` 读写 0x83Cxxxxx 就是跨这条边界）。命名：`pl_to_m_axis`、`ps_clk`、`block_rx_dma_to_ps`。
- **FDD = 频分双工**（收发不同频、可同时）；**TDD = 时分双工**（同频、分时）。WiFi 与 openwifi 都是 TDD（这就是 CSMA/CA 与 ACK 时序要放在 `xpu` 硬件里的原因）；AD9361 芯片两种都支持（BD 里有 `util_ad9361_tdd_sync`、`axi_ad9361/up_txnrx`）。
- **ADI = Analog Devices**（亚德诺）：芯片（AD9361）+ HDL 参考设计（BD 里 8 个 `analog.com:user:*`）+ 内核分支（`2026_R1`）。openwifi 建在其上，非从零写 HDL。
- **`adc_data_i0/q0/i1/q1`**：后缀 **0/1 是 RX 通道号（RX1/RX2），不是 I/Q 序号**。BD 实测 i0→`util_ad9361_adc_fifo/din_data_0`、q0→`_1`、i1→`_2`、q1→`_3`；`rx_intf.v:237-238` 合成 `sample0={I0,Q0}`（chain0）、`sample1={I1,Q1}`（chain1）。"路"的口径：天线/通道 2、复基带 2、实数 ADC 流 4（零中频每通道 I/Q 各一个 ADC 核）。上限 **2 路复基带**（AD9361 2T2R；两 RX **共享同一 RX LO** → 只能同频，是 2×2 MIMO/分集，不是两台独立信道接收机；"4 路 RX" 需两颗芯片）。E316 的 4 个 SMA ≠ 4 路 RX。
- 第二路唯一的消费者是 side_ch（`sample1_in` → `side_ch.v:319` 的 `iq1`），对应官方 app note **`doc/app_notes/iq_2ant.md`** 的 "dual antenna capture"（主天线 rx0 通信+抓 IQ、监听天线 rx1 相干同步抓 IQ，用途是捕获碰撞；仅 AD9361 板支持）。openofdm_rx 只吃 `sample0`。
